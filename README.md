# RAG Chunking: Сравнение стратегий чанкинга для RAG
## 📌 Суть проекта
Сравнить разные стратегии чанкинга для RAG

В src реализован RAG-pipeline, подготовленный для использования в сравнении стратегий:
- **utils.py** - Классы для загрузки корпуса документов
- **chunkers.py** - Классы стратегий чанкирования
- **vector_store.py** - Класс для векторной базы данных + ретривера(Chroma)
- **generator.py** - Класс, который создает промпт и генерирует ответ
- **pipeline.py** - Класс для интеграции всех компонентов

## 📂 Используемый датасет
Оценка проводится на датасете [MultiHopRAG](https://huggingface.co/datasets/yixuantt/MultiHopRAG)

## ⚙️ Сравниваемые стратегии чанкинга
1. **Фиксированный размер (Fixed-size chunking)**  
   Текст разбивается на блоки фиксированной длины (по количеству символов/токенов) с возможным перекрытием. Простейшая стратегия, не учитывающая структуру документа.

2. **Рекурсивный чанкинг (Recursive chunking)**  
   Используется иерархия разделителей: сначала пытается разделить по абзацам, затем по предложениям, и только потом прибегает к фиксированному размеру. Позволяет сохранить смысловую целостность абзацев и предложений.

3. **Семантический чанкинг (Semantic chunking)**  
   Предложения группируются по близости их векторных представлений (эмбеддингов). Границы чанков определяются на основе порогового значения косинусного расстояния, что даёт чанки, внутренне однородные по смыслу.

## Фиксированные параметры RAG
Векторная база данных - Chroma
Retriver - sentence-transformers/all-MiniLM-L6-v2
Модель генерации ответов - llama-3.1-8b-instant(temperature=0, max_tokens=256)
Размер чанков - 512
